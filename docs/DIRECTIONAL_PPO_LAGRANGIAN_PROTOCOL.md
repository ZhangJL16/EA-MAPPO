## 2. 方法依据与有限任务适配

参考 [OmniSafe PPOLag 原实现](https://raw.githubusercontent.com/PKU-Alignment/omnisafe/main/omnisafe/algorithms/on_policy/naive_lagrange/ppo_lag.py) 的奖励/成本优势组合，以及 [Lagrange 更新实现](https://raw.githubusercontent.com/PKU-Alignment/omnisafe/main/omnisafe/common/lagrange.py) 的非负投影。PPO clipping、Gaussian likelihood 和采样 KL 停止条件对照本地 SB32.7.1源码；不是宣称逐行复现 OmniSafe 默认配置。

任务首次接触结束，因此

\[
c_t=\mathbf1\{\text{本次转移发生接触}\},\quad
\sum_{t<T}c_t=\mathbf1\{\text{本任务接触}\},\quad
J_C(\pi)=\Pr_\pi(\text{接触}).
\]

保持原导航奖励分项和统一 .01 缩放；目标为最大化缩放后的期望回报，同时约束任务接触概率。完整轨迹返回使成本目标可以直接用不折扣 MC 累计量，不需要把未结束轨迹冒充完整标签：

\[
G_t^C=\sum_{k=t}^{T-1}c_k,\qquad A_t^C=G_t^C-V_C(o_t).
\]

奖励优势仍用 gamma=1、GAE lambda=.95；成本采用 gamma=1、lambda=1。完整期限超时成本为0，但超时不算任务成功。这里对原方法作了明确适配，不能套用无限期折扣收敛定理。

对于固定策略下预定的N个完整任务，每任务等权：

\[
\hat J_C=N^{-1}\sum_i\mathbf1\{F_i\},\qquad
\lambda_{k+1}=\max(0,\lambda_k+\eta(\hat J_C-\delta)).
\]

随后对 \((A^R-\lambda A^C)/(1+\lambda)\) 做联合标准化并使用 PPO clipped surrogate。没有分别白化奖励与成本而隐藏单位变化。\(\lambda\) 的单位对应缩放后的奖励，不是原始奖励单位。

默认探索参数：\(\delta=.05\)、\(\eta=1\)、\(\lambda_0=0\)。5%不是部署合格线或定理要求。每组8任务的接触率估计很粗糙；即使最终50任务零接触，也不能据此以95%置信证明风险小于5%。

## 3. 保持与改变的边界

- 完整1024射线、有序2×16读出、actor256×256、critic256×256和独立actor/critic提取器不变。
- 增加一个257参数的成本线性输出头，与奖励价值头共享critic主干。不是三个critic；没有再增加一个雷达编码器。
- 两组从相同随机初始化开始，不加载训练后的R3/PPO权重。成本头初始为0；初始化总权重哈希必须一致。
- 两组都拟合相同奖励与成本价值函数，使用相同Gaussian、clipping、梯度裁剪和KL停止条件。**唯一实验处理为：乘子根据接触率更新，或固定为0。** 因此控制组不是原封不动的SB3普通PPO，而是专门隔离约束反馈的匹配控制。
- 不加入PID、恢复策略、世界模型、规划器、行为克隆或能耗损失。
- critic共享主干意味着成本回归也影响奖励表征，故不能省掉匹配控制而直接对比旧58%结果。
- 价值头为普通近似回归，无结构性概率范围保证；记录成本预测超出[0,1]的比例，不把它当校准后的安全概率。

## 4. 完整任务采集，而非短任务完成均值

每个更新周期固定策略，为8个worker分别登记一个任务seed；等全部8个完成后再更新。提前结束的worker进入停驻槽位，不再推进物理状态或生成额外短任务，停驻槽位不计为“安全任务”。不足8个的最后一组评估也只计真实任务。

这消除了“先结束的任务被过度统计”的偏差，并使成本MC标签完整，但改变了上一轮512步更新的采样方式。因此两组都使用此采集器，不能将跨采集合同的差异全部归功于Lagrangian。

第一组所有任务都发生接触时，初始MC成本优势全为1；联合中心化会消去这个常数，两个分支的第一次策略更新近乎相同是预期现象，不是乘子符号错误。更大的乘子不能凭空创造安全/不安全动作对比信息。若长期只有失败标签，应检查探索覆盖，而非宣布乘子升高就代表学会安全。

## 5. 预定实验

- 两组顺序运行：Lagrangian，然后lambda-zero control。只占一组8环境和一张GPU，不并发两份主训练。
- **每组64次完整任务更新，共512个预定训练任务**。选择64是为了不把上一轮64次PPO更新压缩为一半；此前32组是预算草案，主实验启动前修订。
- 两组使用相同训练任务seed483600001起、同样初始权重与优化配置。比较相同任务组数，不宣称环境步数相等：不同策略的任务长度不同，记录实际物理步数、梯度更新次数和墙钟。
- 每任务期限4000，故每组最多2,048,000个实际训练policy transitions；这只是任务数×期限上界，不是必须跑满的训练步预算。
- 每组最终对相同50个新开发任务seed593800001起，分别做确定性与随机策略评估。两种执行方式分开统计；只有随机策略评估与训练中的随机策略风险对象直接对应。
- 其中前三个开发任务已经用于机械preflight评估，未用于梯度或根据评估结果选择超参；因此不将这50任务称为完全未查看的最终测试集。
- 主指标是无碰撞到达、接触、超时三项互斥结果；另报告成功样本数和路径比。低碰撞但大量超时不算解决导航。
- 仅一个初始化种子的探索比较，不能据此宣布算法普遍领先或论文创新成立。后续正式500任务评估不在本轮自动触发。
