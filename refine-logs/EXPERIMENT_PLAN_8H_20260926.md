# 8 小时连续研究矩阵：精确基线与 GPU 长视界规划

日期：2026-09-26。独立项目 `/home/zjl/uav_learning_research`。旧项目 `/home/zjl/mappo` 不重开。用户明确要求连续约 8 小时、多种方案、GPU 提速优先；本计划在该授权内启动。

## 核心问题

静态全图、确定性合成能耗模型、同一 600 仿真秒和同一精确联合安全过滤器下，学习策略与解析规划的完成数、碰撞/耗尽/返站失败及计算代价如何比较？更长的局部规划视界是否带来收益；GPU 批量候选预测能否降低长视界候选搜索的计算成本？

不声称 GPU 近似预测是安全证明。所有 GPU-MPC 选出的首动作都经过原始 CPU `certify_policy_block` 和环境执行验证。既有碰撞恢复及惩罚规则不变。

## 冻结方案

| 方案 | 机制 | 地图与指标 | 用途 |
|---|---|---|---|
| 路线补满 / 路线部分补能 | 非学习规则 | 原静态矩阵验证 32–39、测试 40–55；完成数、安全、补能 | 简单基线与部分补能价值 |
| CPU-MPC H1 / H2 | 精确候选认证，0.5/1 秒局部视界 | 同上；候选数及决策墙钟 | 强非学习对照与视界敏感性 |
| PPO 101/202/303 | 51,200 训练决策每种子，13 离散动作 | 同上；三种子分布和安全事件 | 本轮学习基线，不代表全部 RL |
| GPU-MPC H4 / H8 | 批量 324 条近似候选，2/4 秒视界，最多 3 个精确认证 | 先验证 32–35 与测试 40–47 配对；有时间再扩展至全部 8/16 图 | 长视界收益与计算代价 |

GPU 方案并不更改任务持续时间、地图、能耗、动作集、充电曲线或碰撞机制。其候选排序是近似模型，可能劣于 CPU-MPC；无论胜负均报告。验证集只用于冻结 CPU H1/H2 主比较对象，不用测试图调参。GPU H4/H8 均预先固定，不根据结果选择地图或调候选数。

## 运行顺序与墙钟预算

1. 已运行的精确静态矩阵继续，训练已完成；验证和测试自动续跑。它的独立结果目录保留源码及依赖哈希。
2. 同时开启一份**严格 28,800 秒墙钟** GPU 伴随矩阵，单 GPU 进程串行执行 H4/H8，同地图两者成对出现；其他 3 个 CPU 工作进程继续精确矩阵。阶段顺序固定：核心验证 4 图、核心测试 8 图、扩展验证 4 图、扩展测试 8 图。
3. GPU 伴随矩阵到时在最多 20 决策后落盘中断。只对两方案均完成的地图报告描述统计；不足 16 张冻结测试图不得给总体优越结论。
4. 精确主矩阵若在 8 小时之外仍未完成，保持可恢复运行，不把部分地图结果伪装成主实验结论。

实测预算依据：CPU 路线策略 20 决策约 5.39 墙钟秒，CPU-MPC H2 同地图 20 决策约 48.74 秒；GPU H4 单次 324 候选预测＋首个精确认证约 0.54 秒。小样本只能定性说明候选搜索存在提速空间，真实整集速度由每图事件和完整运行日志判定。

## 判断规则与局限

主要安全指标为统一碰撞计数、实际耗尽、返站失败；完成数为 600 仿真秒的任务数。CPU 主比较采用原计划的地图级配对与 bootstrap 区间。GPU H4/H8 的核心问题是同地图的完成数差、候选墙钟、精确认证次数；作为探索性计算方法，不把近似预测误差当成安全保证。若 GPU 速度不增或完成率下降，保留负结果，并进一步分解 GPU 计算、CPU 精确认证与模拟本体成本。

完整安全过滤器和物理仿真依旧在 CPU。将训练和安全认证整体 GPU 化需另一份批量实现与逐物理步一致性验证；本轮不伪称已完成。
